# ComplaintCheck · 起诉状自查工具

> 基于确定性规则引擎的民事起诉状"立案前体检"工具。粘贴或上传起诉状，30 秒内获得逐项检查报告：哪里有问题、怎么改、依据是什么（精确到法条），并可导出 Markdown / PDF 报告。

**法律人工智能应用 · 课程作业 · 开源项目（MIT License）**

## 解决什么问题

民事一审起诉状是立案的"第一道门槛"。大量起诉状因当事人信息不全、诉讼请求不明确、案由与请求不匹配、管辖法院错误、形式要件缺失等问题被立案窗口退回，导致当事人反复奔波。

ComplaintCheck 用 **~35 项确定性规则**（不接大模型，无 AI 幻觉）在立案前帮你拦住这些低级错误：

| 分级 | 含义 | 扣分 |
|---|---|---|
| 🔴 必须修改 | 大概率立案受阻 | -15/项 |
| 🟡 待确认 | 可能被退回补充 | -5/项 |
| 🔵 建议 | 不影响立案 | 不计分 |

输出 **0–100 立案风险分**：<60 分提示"建议修改后再提交立案"。

## 检查项覆盖

- **通用检查（22 项，适用一切民事一审起诉状）**
  - A 形式要件（7）：标题 / 当事人段 / 诉讼请求段 / 事实与理由段 / 具状人落款 / 日期 / 致送法院
  - B 当事人信息（6）：原被告姓名、身份信息、送达信息、身份证号、联系方式
  - C 诉讼请求（4）：编号、金钱请求数额、利息完整性、诉讼费
  - E 事实与理由（3）：时间要素、金额要素、法条引用格式
  - F 管辖（2）：致送法院名称规范、按案由输出管辖规则提示卡
- **案由专项（13 项，按所选案由动态触发）**
  - 民间借贷（4）：借款金额与交付方式 / 还款期限 / 利率超 LPR 四倍 / 仲裁条款冲突
  - 买卖合同（5）：标的物 / 价款支付 / 交货验收 / 违约金标准 / 仲裁条款冲突
  - 侵权责任·人身损害（4）：时间地点经过 / 赔偿项目 / 损失数额依据 / 误工费要素

每条规则均标注法条/司法解释依据，可在页面"检查项溯源"中查看全部规则。

## 隐私承诺

**文书内容仅在内存中处理，不落盘、不上传第三方。** 法律文书包含敏感个人信息，本工具不做任何持久化存储。（上传 .docx 同样仅解析内存字节流。）

## 快速开始

```bash
# 1. 安装依赖（Python 3.10+）
pip install -r requirements.txt

# 2. 启动
uvicorn app.main:app --reload --port 8765

# 3. 打开浏览器
# http://localhost:8765
```

运行测试：

```bash
pytest tests/ -v
```

## 架构

```
complaint-check/
├── app/        FastAPI 应用入口与路由（main.py、api/）
├── core/       规则引擎核心，与具体案由解耦
│   ├── engine.py     规则执行器（加载 YAML → 逐项执行 → 汇总）
│   ├── models.py     Issue / CheckReport 数据模型与评分
│   └── segmenter.py  起诉状结构分段器
├── rules/      检查项规则库（YAML，核心资产）
│   ├── common/       通用规则 A/B/C/E/F（22 项）
│   └── cases/        案由专项规则（民间借贷 / 买卖合同 / 侵权责任）
├── web/        前端单页（文书输入、分级问题清单、原文高亮、报告导出）
├── tests/      规则引擎与 API 单元测试
├── samples/    2 份示例起诉状
└── .github/workflows/ci.yml   CI（pytest）
```

**后端**：Python / FastAPI + PyYAML。规则全部以 YAML 配置承载（判定逻辑 + 建议文案 + 法条依据），引擎与规则解耦——**新增案由只需增加一个 YAML 文件，不改引擎代码**。

**前端**：单页静态页面，`fetch` 调用 `/api/check`；报告的 Markdown 导出与打印 PDF 在前端完成。

## 核心接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/check` | `{text, case_type}` → 体检报告 JSON |
| POST | `/api/check-file` | 上传 .txt / .docx → 体检报告 JSON |
| GET | `/api/rules` | 全部检查项定义（溯源） |
| GET | `/api/cases` | 案由下拉选项 |
| GET | `/api/samples` | 示例文书列表 |

## 设计边界（本期不做）

- 刑事/行政起诉状、上诉状、答辩状（架构预留扩展位）
- 智能改写起诉状正文——只指出问题与建议方向，**不代写文书**
- 对接法院立案系统或实名验证
- 大模型全文改写——所有检查项均为确定性规则引擎，保证结果可复现
