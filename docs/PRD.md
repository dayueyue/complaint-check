## 1. 背景与问题

民事一审起诉状是立案的"第一道门槛"。实践中大量起诉状因以下问题被立案窗口退回或被对方在庭审中钻空子：

- **当事人信息不完整**：被告主体信息不全（无身份证号/统一社会信用代码、地址不明），法院无法送达，直接导致立案失败或公告送达拖延。
- **诉讼请求不明确、不可执行**：如"请求被告赔偿损失"（无数额）、请求项之间逻辑冲突、利息请求无起算日和利率标准。
- **案由与诉讼请求不匹配**：写了违约事实却提侵权之诉，或案由选择错误导致审理路径偏差。
- **管辖法院错误**：合同纠纷未按合同履行地/被告住所地规则选择，被移送或驳回。
- **形式要件缺失**：缺具状人签名、缺证据清单、副本份数不足等。

现有工具要么是面向律师的付费 SaaS，要么是通用法律问答机器人（无法保证规则层面的准确性）。**本工具定位：基于确定性规则引擎的起诉状"立案前体检"，所有检查项可追溯至法条/司法解释依据。**

## 2. 目标用户

| 用户 | 场景 | 核心诉求 |
|---|---|---|
| 普通当事人（主） | 自己写起诉状准备立案 | 别被退回，别犯低级错误 |
| 法学院学生（主） | 课程学习、模拟法庭 | 理解起诉状各部分的规范要求 |
| 初年级律师/实习律师（次） | 快速自查文书 | 出文书前过一遍 checklist |

## 3. 产品定位（一句话）

> 粘贴或上传你的民事起诉状，30 秒内获得一份**逐项体检报告**：哪里有问题、怎么改、依据是什么（精确到法条），并可导出 Markdown/PDF 报告。

## 4. 范围界定

### 4.1 本期做（v1.0）

- **文书类型**：民事一审起诉状（含自然人原告、法人/非法人组织原告）。
- **案由覆盖**：通用检查项（适用于一切民事一审起诉状）+ 3 个高频案由的专项检查：
  1. 民间借贷纠纷
  2. 买卖合同纠纷
  3. 侵权责任纠纷（人身损害赔偿）
- **检查维度**（详见第 5 节）：形式要件 → 当事人信息 → 诉讼请求 → 事实与理由 → 案由匹配 → 管辖法院。

### 4.2 本期不做（明确排除，写进 README 避免 issue）

- 刑事/行政起诉状、上诉状、答辩状（架构预留扩展位，v2 再说）
- 智能改写起诉状正文（只指出问题与建议方向，不代写文书——降低"AI 担责"风险）
- 对接法院立案系统或实名验证
- 大模型全文改写；v1 的所有检查项均为**规则引擎**，保证结果确定性、可复现

## 5. 功能需求（核心：检查项规则库）

### 5.1 检查维度与检查项清单（v1 共 ~30 项）

#### A. 形式要件（通用，7 项）
| # | 检查项 | 判定规则 | 依据 |
|---|---|---|---|
| A1 | 标题规范 | 首行含"民事起诉状"/"起诉状" | 《民事诉讼法》通行文书样式 |
| A2 | 当事人基本信息段齐全 | 存在原告、被告两个信息段 | 同上 |
| A3 | 诉讼请求段 | 存在"诉讼请求/请求事项"段且有编号条目 | 同上 |
| A4 | 事实与理由段 | 存在"事实与理由"段且非空 | 同上 |
| A5 | 具状人落款 | 文末有"具状人/起诉人"署名 | 同上 |
| A6 | 日期落款 | 文末有成文日期且格式合法 | 同上 |
| A7 | 致送法院抬头 | 含"此致 ×××人民法院" | 《民事诉讼法》第122条 |

#### B. 当事人信息（通用，6 项）
| # | 检查项 | 判定规则 | 依据 |
|---|---|---|---|
| B1 | 原告姓名/名称 | 有原告姓名（自然人）或名称（单位） | 《民诉法解释》第209条 |
| B2 | 原告身份信息 | 自然人：性别+出生日期+住址；法人：住所地+法定代表人 | 同上 |
| B3 | 被告姓名/名称明确 | 被告段非空、非"待查" | 《民诉法解释》第209条 |
| B4 | 被告身份信息足以送达 | 自然人：性别、出生日期、住址至少两项；单位：住所地+法定代表人 | 同上 |
| B5 | 被告身份证号/统一社会信用代码 | 检测是否提供（提供=提示"良好"，缺失=提示"建议补充以利送达"，非硬伤） | 立案实务 |
| B6 | 联系方式 | 原告电话是否提供（影响送达） | 立案实务 |

#### C. 诉讼请求（通用 4 项 + 案由专项）
| # | 检查项 | 判定规则 | 依据 |
|---|---|---|---|
| C1 | 请求项编号且非空 | 至少 1 条，逐条以数字编号 | 文书规范 |
| C2 | 金钱请求有明确数额 | 检出"赔偿/返还/支付"类表述但无数额数字 → 高危 | 《民诉法解释》第463条（执行依据明确性） |
| C3 | 利息请求完整性 | 出现"利息"但未同时出现利率标准（LPR/年利率%/月利率%）或起算日期 → 警告 | 借贷/买卖实务 |
| C4 | 诉讼费承担请求 | 提示补充"诉讼费由被告承担"（软提示） | 《诉讼费用交纳办法》 |

#### D. 案由专项（按所选案由触发，见 5.2）

#### E. 事实与理由（通用 3 项）
| # | 检查项 | 判定规则 | 依据 |
|---|---|---|---|
| E1 | 事实段包含时间要素 | 含至少 1 个日期表达 | 证明力实务 |
| E2 | 事实段包含金额要素 | 金钱类请求对应事实段含金额 | 实务 |
| E3 | 理由段含法律依据引用 | 检测"《民法典》第X条"等引用格式，引用格式非法时警告 | 文书规范 |

#### F. 管辖（通用 2 项 + 案由辅助）
| # | 检查项 | 判定规则 | 依据 |
|---|---|---|---|
| F1 | 致送法院名称规范 | 以"人民法院"结尾且非空 | 《民事诉讼法》第122条 |
| F2 | 管辖逻辑提示 | 依据所选案由给出管辖规则提示（如民间借贷：被告住所地或合同履行地；买卖合同：同前 + 协议管辖提示），若起诉状中写明了被告住所地，则校验致送法院与其一致性 | 《民事诉讼法》第23、24条，《民诉法解释》第18条 |

### 5.2 案由专项规则（示例：民间借贷）

- 是否写明**借款金额**与**交付方式**（转账/现金）→ 影响借贷关系成立认定（民间借贷新规）
- 是否写明**还款期限** → 影响诉讼时效起算提示
- 是否写明**利率约定**并超过 LPR 四倍 → **红色高危**：超出部分不受保护（司法解释第25条）
- 有无"约定管辖/仲裁条款"冲突提示 → 若事实段提到协议仲裁，提示诉讼路径可能错误（《仲裁法》第5条）

### 5.3 功能清单（用户视角）

| 功能 | 描述 | 优先级 |
|---|---|---|
| F1 文书输入 | 文本框粘贴 / 上传 .txt .docx（docx 后端解析为纯文本） | P0 |
| F2 案由选择 | 下拉选择通用 / 民间借贷 / 买卖合同 / 侵权 | P0 |
| F3 一键自查 | 调用后端规则引擎，返回结构化检查结果 | P0 |
| F4 问题清单展示 | 按严重度分级展示：🔴 高危（大概率立案受阻）/ 🟡 警告（可能被退补）/ 🔵 建议（加分项）；每项含：问题描述 → 修改建议 → 法律依据（可展开） | P0 |
| F5 高亮原文 | 侧栏展示原文，命中的问题句子/字段高亮定位 | P1 |
| F6 导出报告 | 导出 Markdown / PDF 体检报告（含总分、问题清单、依据） | P0 |
| F7 检查项溯源页 | 静态页面列出全部检查项及其法条依据（体现"可解释性"，课程加分） | P1 |
| F8 示例文书 | 内置 2 份示例起诉状（一份漏洞百出、一份规范）供一键体验 | P0 |

### 5.4 评分模型

输出一个 0–100 的"立案风险分"：高危项每项 -15，警告每项 -5，建议项不计分不扣分；60 分以下提示"建议修改后再提交立案"。分数仅辅助参考，报告中注明"本工具不构成法律意见"。

## 6. 非功能需求

- **准确性红线**：所有规则检查为确定性代码，同一输入永远同一输出；不接 LLM，不出现"AI 幻觉式法条"。
- **免责声明**：页面固定位置 + 导出报告页脚注明"仅供学习参考，不构成法律意见，正式文书请咨询执业律师"。
- **隐私**：文书仅在内存中处理，不落盘、不上传第三方；README 中明确声明（法律文书写敏感信息，这是卖点）。
- **性能**：10 万字以内文书检查 < 2s。
- **可扩展性**：检查项为**配置化规则库**（YAML/JSON 每项一个条目：id、级别、正则/函数规则、建议文案、法条依据），新增案由只加配置不改引擎。

## 7. 技术方案

```
complaint-check/
├── backend/
│   ├── app.py               # FastAPI 入口：/api/check, /api/report
│   ├── engine/
│   │   ├── checker.py       # 规则引擎主循环（加载规则→执行→汇总评分）
│   │   ├── rules_loader.py  # 读取 YAML 规则库
│   │   └── extractors.py    # 结构抽取（当事人段/请求项/日期/金额识别）
│   ├── rules/
│   │   ├── common.yaml      # 通用检查项（A/B/C/E/F）
│   │   ├── jiedai.yaml      # 民间借贷专项
│   │   ├── maimai.yaml      # 买卖合同专项
│   │   └── qinquan.yaml     # 侵权专项
│   └── samples/             # 内置示例起诉状
├── frontend/
│   ├── index.html           # 单页应用（原生 JS 或 Vue3 + Vite，待定）
│   └── report.js            # 报告渲染与导出
├── docs/
│   └── PRD.md
├── README.md
└── LICENSE                  # MIT
```

- 后端：Python 3.10+ / FastAPI / PyYAML / python-docx（docx 解析）/ reportlab（PDF 导出，或前端导出）
- 前端：单页应用，浅色简洁风格；部署：`uvicorn` 本地一键启动，另附 Dockerfile
- 测试：`tests/` 内置对每条规则的单元测试（示例文书 → 期望命中项），GitHub Actions 跑 CI

## 9. 成功标准

1. 两份内置示例文书：漏洞版命中 ≥ 10 项问题且含 ≥ 3 项高危；规范版 0 高危。
2. 每条检查项在报告中有明确法条/司法解释依据。
3. 从 clone 到跑起来 ≤ 3 条命令（`pip install -r requirements.txt && python backend/app.py` 即可）。
